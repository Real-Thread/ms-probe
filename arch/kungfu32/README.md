# KungFu32 栈回溯适配

## 回溯方法

KungFu GCC 在非叶函数入口保存 LR，栈向低地址增长。本适配从当前 SP 向栈内存最高地址扫描，
将对齐字长中的值视为候选返回地址，再检查返回地址前是否为有效的 `LJMP` 调用指令。

当前识别以下调用形式：

- 4 字节直接 `LJMP`；
- 2 字节寄存器 `LJMP`。

适配返回 `LJMP` 指令自身的地址。该方法不依赖帧指针，但普通栈数据仍存在被误判为返回地址的
可能。被内联或尾调用优化消除的函数不会形成独立记录，栈损坏也会减少结果可信度。

## 代码区约束

端口使用以下弱链接符号判断候选指令是否位于可执行区域：

- `__kernel_rom_start__`：Flash 代码区起始地址；
- `__kernel_rom_end__`、`__text_end__`、`__share_code_end__`：共同确定 Flash 代码区结束地址；
- `__data_start__`、`__data_end__`：RAM 执行区域边界。

BSP 链接脚本必须提供与实际内存布局一致的符号。缺失的弱符号取值为 0，相应区域不会匹配。
如果 BSP 使用其他可执行区域，应先扩展代码区判断，避免直接读取无效地址。

## 地址解析

`rt_backtrace()` 输出的地址可直接交给 KungFu 工具链解析：

```sh
tools/ccr1_issue/bin/kf32-addr2line \
    -e Debug/kf32a158-evb.elf -a -f 0x00133b04 0x00133b24 0x00112760
```

必须使用生成这些地址的同一版本 ELF 文件，并保留调试信息。异常现场调用
`rt_backtrace_from_stack()` 时，传入的 SP 应指向异常发生前的线程栈位置，栈范围应来自对应线程
控制块。
